# G5: animation, audio, navigation and UI parity

Contracts that later G5 packages must follow, one section per package, and the "Headed checks for the owner" list at the end. The plan and the status table are in `FABRIC_CONNECTOR.md` ("G5 status"). Nothing in this file has been run in the editor or the game, and no audio device was opened.

## A1: AnimationPlayer and Animation resources

### What exists, and where

| Piece | Where |
|---|---|
| The clip: tracks of any node's properties, in the `.ocanim` `PROP` chunk (`FORMAT_SPECS.md` 9.4c) | `modules/formats` (`OcAnimation::propTracks`, `propClip`, `propLoop`, `propStep`; `OcProp*` types) |
| Sampling one track; the keys a playhead passed; the player | `modules/anim` (`aver/anim/PropAnim.hpp`; `PropAnim.cpp`, `PropPlayer.cpp`) |
| The C seam | `modules/anim.abi` (`Aver.Anim.Abi`, `aver/anim/propanim_abi.h`; `docs/ABI.md` section 2) |
| The converter | `tools/fabric/FabricAnimation.cpp` (Animation, AnimationLibrary, the player node's property ratings); `FabricResources.cpp` routes the resource types |
| The Godot classes | `scripting/csharp/Aver.Fabric/Nodes/Animation.cs` (`Animation`, `AnimationLibrary`), `AnimationPlayer.cs` (`AnimationMixer`, `AnimationPlayer`, `IAnimationAudioTarget`), `AnimationNative.cs` (P/Invoke and the mirrored enums) |

An `Animation` is a handle to a clip in the engine; `AnimationLibrary` holds `Animation` objects by name; `AnimationMixer` keeps the libraries and feeds the engine's `PropPlayer`; every Godot method reads or edits the engine's clip. Without `Aver.Anim.Abi` beside the executable the classes load and do nothing.

### Space and units (the rule a later package must keep)

- `position_3d`, `rotation_3d` and `scale_3d` track values in a clip are engine space (centimetres, +Z up, left-handed) through `aver/formats/AxisMap.hpp`. The converter applies the map; `Animation` takes and returns Godot's metres and axes through `FabricSpace`; the player's output is converted back to Godot's before it is written to `Node3D.Position` / `Quaternion` / `Scale`.
- Every other value (a `value` track, a bezier, a blend shape, method arguments) is the Godot number the node's property takes. A value track on `Node3D.position` is Godot's metres.
- Times are seconds (`double`). Lengths and steps are floats, as in Godot.

### Track paths

`Node/Child:property:subproperty`, relative to the player's `root_node` (default `..`, the parent). Names are looked up with `Node.GetNodeOrNull`; the property is written with `Object.Set` (so a snake_case or PascalCase member, a `position:x` component and a nested resource property `material_override:albedo_color` all work). A bone track (`Skeleton3D:Bone` on a transform type) writes that bone's pose when the node is a `Skeleton3D` (A2); on any other node it is reported once and not applied. A path that names no node logs one warning per player.

### What the player reports (the order is the contract)

`PropPlayer` appends events in the order they happen and `AnimationMixer.DispatchEvents` carries them out in that order:

1. `play()` -> `current_animation_changed` (when the name changed or after a stop) then `animation_started`.
2. Each pass (`Advance`, the idle/physics process, `Seek(update: true)`): `animation_looped` (Aver extension), then the method / audio / sub-player events of every playing animation in track order, then the **applied** marker where the blended values are written to the nodes (discrete key writes first, then the continuous blend), then, when a non-looping animation ended, `animation_changed` (a queued animation took over: `current_animation_changed`, `animation_started`, then `animation_changed(old, new)`) or `animation_finished` (no queue), then `mixer_applied`.
3. Method calls run immediately (`callback_mode_method` = Immediate) or with `CallDeferred` (Deferred, the default).

Weights: the current animation has `1 - sum(blend_left)`, an outgoing one has its own `blend_left`, which falls by `|speed_scale * delta| / blend_time` each pass; weights are normalised per target unless `deterministic`. A new `play()` hands the outgoing animation `1 - sum(blend_left)`. Blend time: the call's `custom_blend` when >= 0, else the table (`from->to`, `*->to`, `from->*`), else `playback_default_blend_time`. The first pass after `play()` does not advance the playhead (Godot's behaviour); the key at the start fires then.

### Decisions that differ from, or add to, Godot (each one tested)

- `animation_looped(name)` exists on `AnimationPlayer` (the task asked for looped); Godot has no such signal.
- After a `Seek` without `update`, the next pass skips the events between the old and the new position and calls only the nearest key in the direction of travel (Godot's "external seek" rule).
- `play()` of the animation that is already playing does nothing (no restart, no new custom speed).
- `Capture`: the capture transition and ease types are accepted and the fade is linear.
- Interpolation at the ends: a non-looping or ping-pong clip holds its first / last key; a linear loop with `loop_wrap` interpolates across the loop point; a cubic first / last segment clamps its missing neighbour to the key itself (this flattens the start).
- A value that has no numeric form (an array, a node path) is stored as Godot Variant text (converted clips) or as a process-local token (scripts); it never blends, the nearest key's value is written.

### Not done (reported as such)

Animation sections and markers (`play_section*`, `set_section*`, `get_section_*`), `AnimationTree`, bone tracks and root-motion output (closed by A2, below), `audio_max_polyphony`, `reset_on_save`, `movie_quit_on_finish`, binary `.anim` / `.res`, the AnimationPlayer's own `libraries` as `SubResource` AnimationLibrary objects inside a `Object(...)` value (the converter writes dictionaries; a hand-written scene may still pass AnimationLibrary objects).

### Level / project keys written by the converter for an AnimationPlayer

`COMPONENT Props` on the node (class `AnimationPlayer`), Godot's names: `libraries` = `{ "": { "idle": Resource("Animations/main_idle.ocanim") }, "extra": { ... } }` (a library is a dictionary of name to clip path; `AnimationPlayer.Libraries` also accepts `AnimationLibrary` objects), `autoplay`, `speed_scale`, `playback_default_blend_time`, `blend_times` (Godot's flat `[from, to, seconds, ...]`), `root_node`, `active`, `deterministic`, `callback_mode_process` / `_method` / `_discrete`, `playback_auto_capture*`, `current_animation`, `assigned_animation`. Clips are `Content/Animations/<scene>_<name>.ocanim` (a `.tres` Animation keeps its own file name).

### Contract for the audio package (S1)

An `.ocanim` audio track holds keys with `value.s` = the stream's **Godot `res://` path** (the converter does not import audio yet; S1's importer decides the Aver asset path and may map it), `startOffset` and `endOffset` in seconds. The player reports, per key hit, `AudioPlay {track path, stream, t0 = start offset (+ how far past the key a seek landed), t1 = end offset}`, and `AudioStop {track path}` when the player pauses, stops or ends. `AnimationMixer` resolves the track path to a node and calls:

1. `IAnimationAudioTarget.AnimationPlayStream(streamPath, startOffset, endOffset)` / `AnimationStopStream()` when the node implements it (S1's `AudioStreamPlayer`, `AudioStreamPlayer3D` should), else
2. `Set("stream", ResourceLoader.Load(streamPath))` when it has a `stream` member, then `Call("play", startOffset)`; stop is `Call("stop")`.

S1 should implement the interface so it can trim the end (`endOffset`), loop-free, and stop when the animation stops. `audio_max_polyphony` is not enforced.

### Contract for A2 (AnimationTree)

Kept for the record: `AnimationMixer` is the base the tree extends; `PropPlayer::mix` is the seam it reuses. What A2 built is below.

### How the tree runs (the contract a later package must keep)

- **The graph is evaluated in managed code, the mix is the engine's.** Each pass `AnimationTree.Advance` runs `TreeRoot.Run(frame, delta, ...)`. Every `AnimationNodeAnimation` it reaches asks the engine player (`treeAdd`) to move that animation's playhead and queue it with the weight and per-track weights the nodes above it accumulated; then `treeMix` mixes them with exactly the AnimationPlayer's rules (weights, discrete keys, method order, audio / sub-player events, `Applied`, `MixerApplied`), and `DispatchEvents` carries the results out. The existing `AnimStateMachine` / `BlendSpace` in `modules/anim` are pose-based (skeletal clips, Unity / UE style, no travel, no switch modes, no conditions over expressions, no property tracks), so they could not host Godot's graph; the player's mix is the one thing both trees share.
- **The tree mixes deterministically** (Godot's `AnimationTree` does): `value = init + sum(weight * (value - init))`, with `init` from the library's `RESET` animation or else the target's first key. An Add node is therefore additive over RESET; a library without RESET adds over the first key of the first animation that touches the target.
- **Filters are per-track weights.** A blend node's filter list is turned into a layer (`In` weight for the listed tracks, `Out` for the others) that the leaves multiply into a weight per track of their clip (`trackWeights`). Pass: in = blend, out = 0. Blend: in = blend, out = 1. Stop: in = 0, out = blend. A filter only acts when `filter_enabled`. Paths are compared as written (`Skeleton3D:Hips`).
- **Time information.** A node returns a `NodeTime` (length, position, direction, loops). `Remain` is what "at end" transitions, one-shot fades and auto-advance read. A step that wraps a loop or bounces reports the end of the cycle it finishes, so an at-end transition sees a loop's last frame.
- **`sync`.** An input whose weight is 0 and whose node is not synchronised is evaluated with `testOnly` (measured, not advanced, nothing queued), as in Godot.
- **Parameters** are `parameters/<node path>/<name>` properties of the tree (`blend_amount`, `request`, `active`, `blend_position`, `transition_request`, `conditions/<name>`, `playback` ...). They are matched **without regard to case** (the level reader lower-cases property keys; Godot's are case-sensitive), registered with their defaults when `tree_root` is set, and settable before it. Node state (a leaf's playhead, a one-shot's timers) is kept by the tree under the node's path and is cleared when `tree_root` changes.
- **The scene form.** A `tree_root` is an `Object(AnimationNodeStateMachine, "states/Idle/node": Object(AnimationNodeAnimation, ...), "states/Idle/position": Vector2(...), "transitions": [from, to, Object(...), ...])`. Dynamic properties (`states/...`, `nodes/...`, `blend_point_N/...`, `input_N/...`, `bones/N/...`, `parameters/...`) go through `GodotObject.TryDynamicSet`; **`Node.ApplyValues` and `ClassDB.Build` now call it when no C# member matches** (a small additive change: a class with no dynamic names behaves as before).
- **AnimationMixer gained** `RootMotionTrack` (wired to the engine), `GetRootMotionPosition / Rotation / Scale` and the three `...Accumulator` getters (Godot space), a virtual `Advance`, and `ShouldStep` (the player steps while playing, the tree while active). A bone track (`Skeleton3D:Bone`) writes the bone pose when the node is a `Skeleton3D`.

### State machine rules (and where they differ from Godot)

- A root machine starts by itself at `Start` (a `Grouped` machine does not). Reaching `End` stops it. A nested machine is restarted when entered with reset.
- Each pass: resolve a `travel()` request (shortest path by number of transitions, then by the sum of `priority`; disabled transitions are no way; no path means a jump, restarting the state when `reset_on_teleport`), then take transitions: the travel path's next step if it is ready, else the lowest-priority automatic transition whose condition and expression hold and whose switch mode is ready (immediate and sync at once, at end when the state's remaining time is within the transition's xfade time), then process the current state and the one fading out. **Up to 8 transitions are taken in one pass** when each is ready (Godot's own chaining count is not documented; this makes `Start -> Idle` and an immediate `travel()` through several states take one frame, skipping the middle states' animation).
- `Sync` starts the next state at the same fraction of its length as the old one has reached. `reset` restarts the next state's playhead (a key at its very start fires).
- `advance_mode` Enabled is for `travel()` only; Auto is automatic. `advance_condition` reads `parameters/<machine path>/conditions/<name>`; `advance_expression` is evaluated by `Expression` with the node named by `advance_expression_base_node` (default the tree itself) as the base object, **properties and methods only** (no signals); a failing expression is false and logs once.
- The cross-fade weight is the xfade curve's baked value at `elapsed / xfade_time`; the fade starts at the beginning of the pass in which the transition was taken, so the first pass already counts one delta.
- `next()` takes the next transition at once, ignoring its switch mode but not its conditions. `travel("Sub/State")` enters the nested machine and then travels inside it.

### Decisions that differ from, or add to, Godot (each one tested)

- Parameters are case-insensitive (above). `AnimationNodeAnimation`'s custom timeline (`use_custom_timeline`, `timeline_length`, `stretch_time_scale`, `start_offset`, `loop_mode`) and `advance_on_start` are stored and rated approximated; the animation's own length and loop mode play.
- `root_motion_local` is stored. Root motion is reported in the track's own space (position and scale deltas add, rotation composes in blend-weighted slerps); the accumulators are the blended absolute values at the playheads, not Godot's running sums. A seek moves the root by nothing.
- Curves: `Curve` and `Curve3D` follow Godot's sampling and baking rules (cubic segments, the bisection that puts baked points one interval apart); the **up vector** of a path is carried along by the smallest rotation from an initial world up (a path that starts vertical starts from -Z), which is not Godot's exact rule. `Curve3D` and the other resources are **Godot-space managed data** (metres, +Y up): the converter writes their `Object(...)` values as the scene has them; the axis map is applied where the engine consumes data (the node transforms, the `.ocanim` tracks), not here, because nothing in the engine reads a `Curve3D`.
- `PathFollow3D` aims -Z along the path and rolls by the curve's tilt in `XYZ` and `Oriented` mode (`Oriented` uses the carried up vector, `XYZ` the world up rolled by the tilt); `Y` yaws only; `XY` pitches and yaws without roll; `None` leaves the basis alone. A `progress_ratio` set before the node has a curve is applied when it gets one.
- `Skeleton3D` is a **pose model, not connected to a skinned mesh**. Bones, parents, rests, absolute local poses (Godot 4: the pose is the local transform, `reset_bone_pose` copies the rest), global poses with overrides (`amount`, `persistent`), `enabled`, `show_rest_only`, bone meta, `bones/N/...` as a scene stores them. The engine's skeleton lives in the animation system's entities (`CSkeletalMesh`, `AnimSystem`) and only the pose-modifier chain reaches the skinning matrices; to pose a mesh from a script a later package must add a pose-input component to that chain (a registered component like `CControlRig`, with an ABI to set a bone's local pose by name hash, applied in `AnimSystem`'s modifier slot). Until then bone tracks and the IK change the model only.
- `SkeletonIK3D` is FABRIK on the chain from `root_bone` to `tip_bone`, then each bone turned by the shortest arc towards its child; the tip takes the target's basis. Godot's solver distributes rotation differently, so poses differ for the same target (rated approximated). `interpolation` is the modifier's `influence`.
- `SpringArm3D` casts from its origin along its +Z for `spring_length` (a ray, or a `CastMotion` of `shape`), every physics step; children are placed at `spring_length * fraction - margin` keeping their own orientation; `GetHitLength` is `spring_length * fraction`. Without a physics world nothing is hit.
- `RemoteTransform3D` copies in the idle pass (Godot copies on a transform notification), so it follows one frame late when the source moves after it in the tree.
- `VisibleOnScreenNotifier3D` tests the box's eight corners against the clip planes of the current camera every idle pass (not the renderer's occlusion). An Enabler sets its target's process mode to its `enable_mode` while seen and to Disabled otherwise, and starts the target Disabled; the enabler itself runs `Always`.
- `Expression` supports literals, identifiers (named inputs, then the base object's members), `.member`, `[index]`, method calls on the base object or a value, about 20 built-in functions, `Vector2/3` / `Color` constructors, and the operators with GDScript's Variant semantics (`**` right-associative, `and`/`or`/`not` and `&&`/`||`/`!`, `in`).

### Not done (reported as such)

`SpringBoneSimulator3D`, `LookAtModifier3D`, `CopyTransformModifier3D` and the other 4.4 modifiers (carriers, unsupported); a skinned-mesh pose seam (above); custom `AnimationNodeExtension` scripts; `AnimationNodeBlendSpace*` `sync` is honoured, but Godot's "blend position snap" is editor-only and not modelled; `reset_ends` resets the left state only; `root_motion_local`; nested `StateMachineType.Grouped` semantics beyond "no autostart"; `Skeleton3D` in the editor's profile / retarget forms (`SkeletonProfile`).

### Level / project keys written by the converter for these nodes

`COMPONENT Props` with Godot's names: `AnimationTree` (`tree_root` as one `Object(...)` value holding the whole graph, `anim_player`, `active`, `deterministic`, `callback_mode_*`, `advance_expression_base_node`, `root_motion_track`, `root_node`, and every `parameters/...`), `Skeleton3D` (`bones/N/name|parent|rest|enabled|position|rotation|scale`, `motion_scale`, `show_rest_only`), `BoneAttachment3D` (`bone_name`, `bone_idx`, `override_pose`, `use_external_skeleton`, `external_skeleton`), `SkeletonIK3D` (`root_bone`, `tip_bone`, `target`, `target_node`, `min_distance`, `max_iterations`, `interpolation`, `use_magnet`, `magnet`), `Path3D` (`curve` as `Object(Curve3D, "_data": {"points": ..., "tilts": ...}, "point_count": n)`), `PathFollow3D` (`progress`, `progress_ratio`, `h_offset`, `v_offset`, `rotation_mode`, `cubic_interp`, `loop`, `tilt_enabled`), `SpringArm3D` (`shape` as an `Object(...)` shape, `spring_length`, `margin`, `collision_mask`), `RemoteTransform3D` (`remote_path`, `use_global_coordinates`, `update_position|rotation|scale`), `VisibleOnScreenNotifier3D` / `Enabler3D` (`aabb`, `enable_mode`, `enable_node_path`). Curves nested in resources are `Object(Curve, "_data": [...], "point_count": n)`. No new project keys; defaults are Godot's, and existing Aver levels have none of these classes.

### Rules a later package must keep

- **Aver.Fabric audio needs `Aver.Audio.Abi`**; without it the classes load and play nothing (`AudioNative.Available`). The first use of `AudioServer` calls `EnsureReady()`: with an output device (the host called `aver_audio_init`) it uses that mixer; with none it makes the offline mixer and steps it from the frame loop (`AudioServer.FrameUpdate`, once per frame) so players still finish. It turns the bus graph on and applies the project's `AUDIO.BUSLAYOUT` once. Tests call `AudioServer.ResetOffline()` for a fresh mixer and render with `AudioServer.RenderOffline(frames)`.
- **The managed side holds no bus model.** Bus count, names, sends, volumes, effects and their parameters live in the engine's `BusGraph`; `AudioEffect` objects hold their values until they are put on a bus (`AddBusEffect`) and then forward every property change to the engine effect(s) they are bound to (`NativeIds`). An effect from a loaded layout is wrapped on first `GetBusEffect` and reads the engine's values. A layout apply or `ResetOffline` invalidates previously fetched effect objects (documented in `SetBusLayout`).
- **Managed defaults equal the engine's.** Each `AudioEffect*` property declares Godot's default in the C# accessor; `AudioTests` "every managed default equals the engine's" adds every class to a bus and compares every property with the engine's table. A new effect parameter needs both sides.
- **Streams.** A file stream (`AudioStreamWav/OggVorbis/MP3`) is handed to the engine once per audio session (`AudioServer.Generation`); WAV data in the resource (`Data`, 8/16-bit) is decoded to float and loaded as PCM; files over 6 MB (and no custom loop) are streamed from disk. `Resource("Audio/x.wav")`, `Resource("x.wav")` and Godot's own `res://x.wav` all find the converter's copy (`ResourceLoader` falls back to `Audio/<path>`), so animation audio tracks and `load("res://...")` work. The Godot class `AudioStreamWAV` is also known to `ClassDB` under that spelling.
- **Scene values.** The composite streams read the properties Godot stores: Randomizer `streams_count`, `stream_N/stream`, `stream_N/weight`, `playback_mode`, `random_pitch`, `random_volume_offset_db`; Playlist `stream_count`, `stream_N`, `shuffle`, `loop`; Synchronized `stream_count`, `stream_N`, `stream_N/volume`; Interactive `clip_count`, `clip_N/name|stream|auto_advance|next_clip`, `initial_clip`; effects take indexed names (`voice/2/delay_ms`, `band_db/1000_hz`) through `TryDynamicSet`. The converter writes a WAV with import-time loop settings, or an `.ogg` / `.mp3` with a loop, as `Object(AudioStreamWAV, "source_path": "Audio/x.wav", "loop_mode": 1, "loop_begin": 0, "loop_end": 0)` (`source_path` is an Aver extension on `AudioStreamFile`); a plain file is `Resource("Audio/x.wav")`.
- **Players.** `max_polyphony` cuts the oldest playback when exceeded (no `finished` for a cut sound); `finished` fires once when the last playback of a player has ended; `stop()` fires nothing; `playing = true` before the node is ready starts it when it is; a tree pause pauses the voices at once (`NotificationPaused`); a bus name is looked up every frame and an unknown one plays on Master. `IAnimationAudioTarget` is implemented by both players: `AnimationPlayStream(path, start, end)` loads the stream, sets it and plays from `start`, and `end` is Godot's `end_offset` (seconds cut off the END: the player stops at `length - end`).
- **3D.** The listener is the current `AudioListener3D` (the first in the tree is current), else the current `Camera3D`, else the origin looking down -Z (`AudioServer.UpdateListener`); a source's engine position is `FabricSpace.ToAverPosition(GlobalPosition)`; the sound is projected along the node's -Z; Doppler uses the emitter's own tracked velocity (`DopplerTracking` idle or physics step) and the current camera's (`Camera3D.DopplerTracking`, added by S1). `audio/general/3d_panning_strength` defaults to 0.5 (`ProjectSettings.GetSetting`).

### Decisions that differ from, or add to, Godot (each one tested)

- `AudioStreamPlayer.playing`, `stream_paused`, `seek`, `get_playback_position`, `get_stream_playback`, `max_polyphony` follow Godot; `mix_target` is stored (stereo output only) and `playback_type` is stored (every sound is a stream).
- The attenuation filter's high shelf uses Godot's shelf coefficients with the filter gain as `A`, so the high end settles at `gain^2` (Godot's own formulas as read); distance gain and the cone follow the documented formulas.
- Effects marked approximate in `AUDIO.md` section 10 keep Godot's parameter names, ranges and defaults but not its algorithm (PitchShift is time-domain, Reverb is Freeverb-style, the EQ bands are peaking filters, Limiter / HardLimiter are not Godot's).
- `AudioStreamPlaylist.fade_time` and `AudioStreamInteractive` transition rules are stored by the report only; playlist entries play back to back and interactive clips switch at once.
- `AudioStreamWAV` ping-pong and backward loops play forward; IMA ADPCM and QOA data are refused with a warning.
- `AudioServer.get_bus_peak_volume_*_db` read the last block's peak after volume and effects; `get_output_latency` / `get_time_to_next_mix` are constants; the driver name is "Dummy" offline and "Aver" otherwise.

### Space and units (the rule a later package must keep)

- The managed API speaks Godot: metres, +Y up, `Rid` handles. Every position crosses through `FabricSpace` (`NavSpace` in `NavigationNative.cs`) and becomes engine centimetres; lengths read back are divided by 100. **Costs, layers and weights are unitless and cross unchanged.**
- A `NavigationMesh` is Godot-space managed data (like `Curve3D`, A2): vertices are in the space of the node that holds it. The region pushes `GlobalTransform * vertex` to the engine through the axis map when it enters the tree, when the mesh changes and when the node moves (next physics frame). The converter therefore writes the mesh as `Object(NavigationMesh, ...)` in Godot numbers and applies the axis map only to the region node's own transform, as for every node.
- `AStar3D`, `AStar2D` and `AStarGrid2D` are plain data structures: values cross as the numbers the script gave, with no axis map and no units.
- A `Rid` for a navigation object is the engine id as `ulong`. A stale handle answers neutral values (`false`, `0`, an empty array) and never throws.

### How the nodes run (the contract)

- **One pump per physics frame.** The first navigation node that processes in a physics frame runs `NavigationServer3D.Process`: finished async bakes are applied (and their callbacks run), region / link / obstacle nodes that moved push their transforms, every map is rebuilt if it changed and its avoidance is stepped, then agents with a computed safe velocity emit `velocity_computed`. A query always sees every change made before it (the map rebuilds itself first); `map_force_update` is there for the signal and the iteration id.
- **A region needs a map.** A node joins `World3D.NavigationMap` (the default map, made on first use) when it enters the tree unless `set_navigation_map` gave it another; leaving the tree frees its object.
- **NavigationAgent3D** finds its path from its parent's global position at most once per physics frame, when a script reads `get_next_path_position()`, `is_navigation_finished()` or `get_final_position()`. The path is recomputed when none exists, when `target_position` is set again (even to the same value), or when the parent is further than `path_max_distance` from the segment it is on. Waypoints are passed when the parent is within `path_desired_distance`; each pass emits `waypoint_reached({position, type, rid, owner})` and, for a link point, `link_reached` after it. Reaching the last point emits `target_reached` (only if the parent is within `target_desired_distance` of `target_position`, once per target) and then `navigation_finished`. The agent moves nothing. `path_height_offset` is subtracted from every position it reports and compared against.
- **Avoidance** is the crowd's ORCA in the ground plane: `NavigationAgent3D.velocity = v` sends the parent's position and the wanted velocity; after the next physics frame's navigation step the agent emits `velocity_computed(safe)`. Agents see each other when `avoidance_mask & other.avoidance_layers != 0`; `time_horizon_obstacles` > 0 makes wall obstacles count. The vertical part of the wanted velocity is kept (`keep_y_velocity` false zeroes it). `use_3d_avoidance` is stored.
- **Obstacles**: a round `NavigationObstacle3D` (`radius` > 0, no vertices) is an agent that never gives way; one with `vertices` (three or more, in the node's space) is a wall polygon: clockwise seen from above keeps agents out, counter-clockwise keeps them in. With `affect_navigation_mesh` it also cuts a hole (its shape, then the agent radius around it) when a mesh is baked from the scene; `carve_navigation_mesh` is stored and does not change the bake (Godot's separate discard / carve passes are one cut here). A running map is never re-carved, as in Godot.
- **Baking.** `NavigationRegion3D.bake_navigation_mesh(on_thread)` parses the scene below the region (`geometry_parsed_geometry_type`, `geometry_collision_mask`, `geometry_source_geometry_mode` and `geometry_source_group_name`) into a `NavigationMeshSourceGeometryData3D`, gathers every input on the calling thread, and runs the engine baker (a worker thread for `on_thread`). `bake_finished` is emitted when the mesh was filled (from the frame pump for a threaded bake). Source geometry with no triangles clears the mesh and still runs the callback, without an error (Godot's rule). **Readable geometry**: `BoxMesh`, `ArrayMesh` and the collision shapes `BoxShape3D` and `ConcavePolygonShape3D` give exact triangles; sphere, capsule, cylinder and convex shapes are read as their bounding box (warned once); any other `Mesh` (including a converted `.ocmesh`) gives nothing.
- **Costs.** `enter_cost` is added once when a path enters the region or uses the link, `travel_cost` multiplies the distance travelled in it. Both are clamped at zero in the node.

### Decisions that differ from, or add to, Godot (each one tested)

- Baking is the engine's heightfield baker, not Recast: polygons are rectangles-and-triangles that fit a plane, not Recast's contour polygons. `sample_partition_type`, `region_merge_size`, `edge_max_error` and `detail_sample_distance` are stored and ignored; `vertices_per_polygon` 3 triangulates.
- `path_metadata_flags`: types, rids and owner ids are filled; `include_original_ids` is accepted and fills nothing (a navigation mesh has no source ids here). `pathfinding_algorithm` has the one value, A*.
- A query's start or target that is off the mesh snaps to the closest polygon by distance and height, and the path ends there (`reached_target` false, `is_target_reachable()` false when the end is further than `target_desired_distance` from the target). Floors that overlap in plan are not joined without a ramp or a link.
- `NavigationLink3D` ends attach to the nearest polygon within `link_connection_radius` (1 m by default); an end with no polygon near attaches to nothing and the link does nothing.
- `NavigationServer3D.map_set_up` is accepted and ignored (the map is always +Y up); `map_get_random_point` draws from a managed `RandomNumberGenerator` (not seedable by the script).
- `AStarGrid2D`: `update()` returns at once when nothing changed since the last one (Godot's rule) and clears solidity and weights otherwise; `clear()` empties the region; the isometric cell shapes only change point positions (Godot's formulas), searches run on the square grid; jump-point search returns the jump points, not every cell. `size` sets the region's size and keeps its position.
- `AStar3D._compute_cost` / `_estimate_cost` overrides are called from the search (native to managed, one call per edge expansion); a cost function that throws is logged and costs 1. A class that overrides neither runs entirely in the engine.
- The agent's `avoidance_enabled`, `radius` and the rest are pushed whenever they change; `debug_enabled*` are stored and draw nothing.
- **Two fixes to the GDScript converter (F4b) that navigation scripts needed**, both covered by `GdScriptConvertTests` "gdscript map: navigation ...": an override of a runtime virtual returns what the virtual returns (`func _compute_cost(...) -> float` over the C# `float` virtual was a `double` and did not compile), and GDScript's `Vector2i` / `Vector3i` / `Vector4i` / `Rect2i` name the runtime's `Vector2I` / `Vector3I` / `Vector4I` / `Rect2I` (they were read by name at run time before).

### Not done (reported as such)

Recast's partition types, detail meshes and exact polygon output; 3D (spherical) avoidance; carving a running map; the per-obstruction `carve` flag of `NavigationMeshSourceGeometryData3D` (any obstruction cuts, and `carve_navigation_mesh` does not change a bake); `NavigationPolygon` and every 2D navigation class (out of scope); `NavigationRegion3D` bake from a converted `.ocmesh` (the geometry is not readable from managed code: bake from collision shapes, or bake in the editor and let the converter carry the polygons); `NavigationServer3D` debug and `*_debug` settings; map-change callbacks other than `map_changed`; `AStarGrid2D` isometric path costs (positions only).

### Level / project keys written by the converter

`COMPONENT Props` with Godot's names: `NavigationRegion3D` (`navigation_mesh` as `Object(NavigationMesh, "vertices": PackedVector3Array(...), "polygons": [PackedInt32Array(...)], "cell_size": ...)` with every baking parameter the scene stored, `enabled`, `navigation_layers`, `enter_cost`, `travel_cost`, `use_edge_connections`, and **`bake_on_ready` (an Aver.Fabric extension, true when the mesh has no polygons)**), `NavigationLink3D` (`enabled`, `bidirectional`, `navigation_layers`, `start_position`, `end_position`, `enter_cost`, `travel_cost`), `NavigationObstacle3D` (`radius`, `height`, `vertices`, `velocity`, `avoidance_enabled`, `avoidance_layers`, `affect_navigation_mesh`, `carve_navigation_mesh`, `use_3d_avoidance`), `NavigationAgent3D` (placed as a plain node with no transform: every property in the table of `FabricNav.cpp`). ### Space and units (the rule a later package must keep)

- UI space is **pixels, origin top-left, +Y down** (Godot's canvas). No axis map and no centimetres: a Control has nothing to do with the 3D world. The window's pixels are `aver_ui_viewport`; the visible rectangle Controls lay out in is `Window.GetVisibleRect()` (the window divided by the scale factor, or the base size when a stretch mode is on).
- The pointer is the one the host sets for the UI (window pixels, `aver_ui_pointer`); the GUI maps it through the stretch (`Window.WindowToContent`) so a Control sees UI-space positions. A point in a letterbox bar maps outside the visible rectangle.
- Colours cross as straight 0xAABBGGRR; the draw list premultiplies. Godot `Color` floats stay floats in the managed API.

### How a Control runs (the contract U2 builds widgets on)

- **Layout is deferred and flushed.** Anything that changes a minimum size or asks for a sort queues work (`Gui.Defer`); `Gui.FlushLayout` runs at the end of each idle frame, before drawing and before input. A test calls `Settle()`. Reads (`GetRect`, `Size`, `GetCombinedMinimumSize`) after a change but before a flush can be stale, as in Godot.
- **A widget overrides `_Draw`, `_GetMinimumSize`, `_GuiInput`** and reads its look through `GetThemeStylebox / Color / Font / FontSize / Constant / Icon` under its own class name. Drawing is **recorded**: `_Draw` runs only after `QueueRedraw()` (a size or theme change asks for it) and fills `CanvasItem.Commands`; the GUI replays them every frame (modulate, clipping, the stretch transform). A recorded `draw_string` is a placeholder until U2 gives it a font and the text engine (`aver_ui_text_block`): the baseline is placed at 0.8 of the font size.
- **A class the runtime does not have yet** (`Label`, `Button`, `LineEdit`...) is a `Control` whose `_class` Prop becomes `_class` meta (`Node.ApplyValues`); `GetThemeClassName()` and the theme type list use it, so a project theme's `Button/styles/normal` already answers for a carrier. U2 adds the real classes to `ClassDB`; a level that names one by `_class` keeps working because the class placement wins over the carrier.
- **The theme chain** is the control's own `theme`, each parent Control's theme up the tree, the project theme (`ThemeDB.GetProjectTheme()`, the `UI.THEME` key), then the built-in default. For one lookup the themes are tried nearest first and, inside one theme, the types in order: `theme_type_variation`, the base types it names (`Theme.SetTypeVariation`; the nearest theme that declares the variation says its base), then the class chain (`Button`, `BaseButton`, `Control`: only classes Aver.Fabric defines, or `_class` and then them). A `theme_override_*` / `add_theme_*_override` wins over everything. `theme_changed` goes down the tree when a theme, a variation or an override changes.
- **The input chain** (Godot's order, on top of the G1 chain): every node's `_Input`, then the GUI, then `_UnhandledInput`. The GUI gives a mouse event to the topmost visible Control whose rectangle (or `_HasPoint`) holds the point, skipping `Ignore`; `Stop` ends the chain there, `Pass` hands it to the parent Control with its coordinates, `accept_event()` ends it; an event nobody stopped reaches `_UnhandledInput`. A pressed control keeps the pointer until release (motion and the release go to it wherever the pointer is). `mouse_entered` / `mouse_exited` follow the hit control. Keys go to the focused control first; an unhandled `ui_focus_next` / `_prev` / arrow key moves focus.
- **Focus** needs `focus_mode` Click or All; `grab_focus`, `release_focus`, `has_focus`, `focus_entered / exited`, `focus_neighbor_*` and `focus_next / previous` resolve as node paths; with none set, Tab follows tree order and an arrow key the nearest focusable control in that direction.
- **Tooltips** appear after `gui/timers/tooltip_delay_sec` (`UI.TOOLTIPDELAY`, 0.5 s) over a control whose `_GetTooltip` (default `tooltip_text`) is not empty, are looked up through `Pass` parents, vanish on any press or when the pointer leaves, and can be replaced by `_MakeCustomTooltip`'s control (in the tree, on top, at the pointer, freed with the tooltip). The default tooltip is drawn from the `TooltipPanel` / `TooltipLabel` theme items on the UI layer 3 (`AVER_UI_LAYER_TOOLTIP`).
- **Drag and drop** starts when the pointer has moved ten pixels with a button down over a control whose `_GetDragData` returns a value (or at once with `force_drag`); `set_drag_preview` puts the preview control at the pointer (it ignores the pointer); the control under the pointer is asked `_CanDropData` (Pass parents after it), release calls `_DropData` with local coordinates, `NotificationDragBegin` / `DragEnd` go to every control, Escape cancels; the source gets no events while dragging.

### Decisions that differ from, or add to, Godot (each one tested)

- **Style box drawing is tessellation, not Godot's canvas shapes.** Corner arcs have `corner_detail` segments; the border is a ring between the outer and inner outline (its colour splits per side at the 45-degree point, or blends with `border_blend`); the shadow is the box shifted by `shadow_offset` with a feather of `shadow_size`; anti-aliasing is a coverage fringe of `anti_aliasing_size` pixels. Godot's falloffs differ in detail: the converter rates `shadow_*`, `skew` and `anti_aliasing*` approximated. `skew` leans the whole box by half the value each way.
- Per-side border colours (`BorderColorLeft/Top/Right/Bottom`) are an Aver.Fabric extension; Godot has one `border_color`.
- **Rotation and scale are applied to the hit area and the global rectangle only.** The UI draw list has no rotation, so a rotated Control's style boxes and rectangles are drawn upright (rated approximated). A container resets a child's rotation and scale when it places it (Godot's `fit_child_in_rect`).
- **Stretch**: `canvas_items` lays Controls out at the base size and scales the draw; `viewport` is laid out the same way (Godot would also render the whole scene at the base size and scale the picture; here the 3D picture is untouched). The bars of a letterboxed window are drawn black by the GUI over whatever the scene drew; the 3D camera still sees the whole window. `integer` scale mode keeps whole multiples when the window is at least the base size.
- **ScrollContainer** scrolls through `scroll_horizontal / vertical`, `follow_focus` and the wheel; the scroll bars are **not nodes** (their room is reserved, nothing is drawn, no dragging a bar). U2 adds `HScrollBar` / `VScrollBar`.
- Focus search by arrow key is "nearest by the gap, with a penalty for sliding sideways" (Godot's segment search can pick differently on irregular layouts).
- `Font` / `FontFile` hold a path only; a theme's `default_font` and `fonts/...` are carried to the `.octheme` and read back, but nothing draws with them before U2. `FontVariation`, `SystemFont` and bitmap fonts are not converted (reported).
- A `Theme` item of the default theme is Aver's own approximation of Godot's default look (dark panel greys, 4 px style box margins, 16 px font); it is data (`UiThemeSheet.cpp`), not Godot's theme resource.

### Text metrics (the rule the numbers in the tests follow)

- A width comes from the engine (`aver_ui_text_measure`, with the font's **family** and style flags) when the engine has a face, else from a fixed fallback: **half an em per character, a tab as four, a line 1.2 em tall, the baseline at 0.8 of the line**. A headless run, and every test, has no face, so every number in the tests is a count of characters times 8 at 16 px. `UiText.WidthProvider` / `LineProvider` replace the measuring (a host or test), `UiText.ResetForTests()` clears them.
- Text is **broken in managed code** (spaces, after hyphens, between CJK characters; arbitrary mode anywhere) and each line is drawn on its own, so what a control reports as its minimum size is what it draws. The engine's UAX #14 breaking, bidi and shaping apply inside a line.
- A **font is a family** of the engine's font set. The converter writes `Content/UI/Fonts.ocfonts` with one family per font file named after the file's stem (`Fonts/ui/Inter-Bold.ttf` is family `Inter-Bold`, `weight=bold` when the name says bold or heavy, `italic` when it says italic), each ending in `SYSTEM auto` and `BITMAP legacy`, and the default family first (`gui/theme/custom_font`, else the project theme's `default_font`, else the first file). `Font.Family` is that stem, so a `FontFile`, a `FontVariation` over one and a font named by a theme all reach the same family. A control with no font draws with the font set's default family.
- Bold and italic ask the family for those faces (`FLAG_BOLD` / `FLAG_ITALIC` on the draw command); the engine has no synthetic bold, and an italic missing from the family is sheared by 0.2 (docs/GAME_UI_TEXT.md).

### How the widgets run (the contract a later package keeps)

- A widget overrides `_Draw`, `NativeMinimumSize` and `_GuiInput` like U1's, reads its look from the theme under its Godot class name (the class chain is the C# inheritance, which follows Godot's: `CheckBox` is `Button` is `BaseButton`), and **records**: `DrawTextLine`, `DrawStyleBox`, `DrawRect`, `DrawTextureRect` and the clip pair. `Texture2D.EngineHandle` 0 (the host has not given the texture a handle) draws nothing, as in U1.
- **Signals follow Godot's order**: a press is `button_down`; `pressed` comes on the release (or on the press when `action_mode` is press), preceded by `toggled` for a toggle button, then `button_up`. A button group's other members release first (their `toggled(false)`), then the group says `pressed`, then the pressed button says `toggled(true)`; pressing the pressed button of a group again keeps it pressed and says `toggled(true)` and `pressed` again (Godot's order; `allow_unpress` lets go). A `PopupMenu` says `id_pressed` then `index_pressed`, after toggling a check item, and hides the menu and the menus it was opened from. A tab click says `tab_clicked`, `tab_selected`, and `tab_changed` when the tab is new. A Tree selection says `cell_selected` then `item_selected` (multi mode: `multi_selected` only). `Range.value_changed` comes only when the snapped value differs; setting a `LineEdit` / `TextEdit` / `Label` text from code emits no change signal.
- **Popups are top-level Controls** (`PopupWindow`), hidden until `popup()` / `popup_centered()` / `popup_centered_ratio()` / `popup_centered_clamped()` / `popup_on_parent()`. The GUI keeps their list: the topmost shown popup is hit first, they are drawn last on the overlay layer, a press outside closes a `Popup` (menus, pickers) and is used up, an `Exclusive` popup (dialogs) also swallows it, Escape closes the topmost one unless a focused control took it. `OptionButton`, `MenuButton` and `ColorPickerButton` own their popup and put it under the tree's root while it is shown, so it is not one of their children.
- **Scene names**: items arrive as `popup/item_N/{text,id,icon,disabled,separator}` (OptionButton, MenuButton), `item_N/{text,id,checkable,checked,separator,disabled,icon,submenu,shortcut}` (PopupMenu), `item_N/{text,icon,selectable,disabled}` (ItemList), `tab_N/{title,icon,disabled,hidden}` (TabBar); a TabContainer's tab names are its children's names, or their `_tab_name`, `_tab_icon`, `_tab_disabled`, `_tab_hidden` metadata. A `selected` / `current_tab` written before the items waits for them. A `button_group` is `Resource("ButtonGroups/<name>.ocbuttongroup")`: one path is one group (the loader makes it), `_unpress` before the extension is `allow_unpress`.
- `RichTextLabel`: `text` is the BBCode source (parsed when `bbcode_enabled`; turning it on re-parses); `append_text` always parses and does not change `text`; every way of filling it makes the same item stream (`DumpDocument()`), which the layout replays with a style stack.

### Decisions that differ from, or add to, Godot (each one tested)

- **Popups are Controls, not Windows.** `Popup`, `PopupPanel`, `PopupMenu`, `AcceptDialog` and `ConfirmationDialog` derive from `PopupWindow : Control`; `get_window()`, embedded-window decorations, several operating-system windows and `Window` as a base class do not exist. A dialog draws its title and a panel of its own; the title bar cannot be dragged. Rated approximated.
- **Line breaking is managed code**: a word wider than the line overflows in `Word` mode, breaks by characters in `WordSmart` and `Arbitrary`; justification (`[fill]`) is done for rich text only, a `Label`'s `justification_flags` are stored.
- **A `Label`'s trim**: `TrimChar` and `TrimWord` cut the line and drop a trailing space; ellipsis modes append `ellipsis_char`.
- **`visible_characters` counts every character but the newline**, before shaping, in every `visible_characters_behavior`.
- **ScrollBar, Range and slider arithmetic is Godot's** (value snapped to the step then to `max - page`, `exp_edit` through log2, the grabber centred on the pointer within the width less one grabber). The default theme has no grabber image, so the knob is a flat disc 16 px wide.
- **Tree**: text cells are not edited in place (`edit_selected()` is false); check cells toggle on a click, range cells keep their step; folding with the arrow, the left / right keys and a double click activates; the scroll bar is not drawn (the wheel scrolls).
- **`ItemList` / `TextEdit` / `Tree` / `RichTextLabel` scroll bars are not drawn**; `ItemList.get_v_scroll_bar()` and `RichTextLabel.get_v_scroll_bar()` return detached bars holding the position. `ScrollContainer`'s bars are drawn and draggable.
- **`TextEdit`**: single caret, no syntax highlighter, gutters, folding, minimap, drag-and-drop of selected text, context menu or IME; soft wrapping at the width (`wrap_mode` boundary); undo keeps whole-text snapshots.
- **`LineEdit`**: no clear button, no context menu, no virtual keyboard, the caret does not blink (stored); the clipboard is an in-process buffer (the host has no clipboard seam).
- **`RichTextLabel`**: `[b]` / `[i]` ask the family for the faces (a theme's `bold_font` / `italics_font` / `bold_italics_font` / `mono_font` win); the built-in effects use Godot's formulas as documented (wave: `sin(freq * t + (range + index) / 4) * amp / 10` upwards; tornado: `radius` on a circle at the same phase; shake: a hashed direction of length `level` held for `1 / rate`; fade: `1 - (index - start) / length`; rainbow: `hue = -freq * t + index / 20`), the exact phases of Godot's source may differ; a custom `RichTextEffect` is called per character with `Range`, `RelativeIndex`, `AbsoluteIndex`, `ElapsedTime`, `Env`, and can offset, recolour or hide it; a table's columns are as wide as their widest cell, shrunk towards their longest word when the table is too wide; `get_parsed_text()` separates a table row's cells with a tab and rows with a newline (assumed); images need an engine texture handle to appear; hints are shown as tooltips.
- **`TextureProgressBar`**: linear and bilinear fills are exact; a radial fill keeps its angles (`get_radial_angles()`) and is drawn as a left-to-right reveal (the draw list has no wedge).
- **`ColorPicker`** is the simple picker: saturation / value square, hue and alpha bars, presets; no hex field, sliders, wheel shapes or screen sampler.
- **`TextureRect` / `TextureButton` / `NinePatchRect`** draw only with an engine texture handle (U1's rule); their sizes and stretch rectangles are exact.
- **`PopupMenu`** shortcuts and accelerators trigger while the menu is shown, or always when the item was added with `global`; submenus open on hover or the right key; the check mark, radio dot and arrow are flat shapes.
- **`FontVariation`**: `variation_embolden` above zero asks for the family's bold face, an x skew in `variation_transform` for the italic one; spacing, OpenType features and variable-font axes are stored.
- **MSDF, OpenType GSUB and variable fonts: not done, and why.** The engine rasterises coverage glyphs with stb_truetype at the drawn size; it has no signed-distance-field atlas, no GSUB / GPOS shaper (only kerning and Arabic joining) and no variable-font axes. MSDF would be a new atlas format plus a pixel shader in `Aver.Render.UI` (no new library; a GPU run to prove it); GSUB and variable fonts would need a font-shaping library (HarfBuzz is the usual one) or a hand-written subset reader. `multichannel_signed_distance_field` and the hinting properties are stored and rated approximated; ask for a dependency decision before either is built.

### Not done (reported as such)

Menus beyond what a `PopupMenu` does (`MenuBar`, `FileDialog`, native menus), `CodeEdit`, `GraphEdit` / `GraphNode`, `VideoStreamPlayer` (a carrier), `Window` as a class, `SubViewportContainer` details beyond R5, in-place editing in `Tree`, scroll bars on `ItemList` / `TextEdit` / `Tree` / `RichTextLabel` (position only), screen-reader accessibility, IME, right-to-left layout of containers (`layout_direction` is stored), `RichTextLabel` text selection by double and triple click and context menu, `[dropcap]`, `[char]`, `[hr]`, `[opentype_features]`, `[pulse]`, `ruby`, vertical text, drag and drop between `Tree`s, the `Tree` drop modes, tooltips for tree buttons, per-item tooltips on tabs of a `TabContainer` beyond the text, `Texture2D` handles for UI (U1's open item), a real clipboard, `Label.tab_stops`. Nothing here ran in the editor or the game.

### Level / project keys written by the converter

No new project key. New content: `Content/UI/Fonts.ocfonts` (above; `docs/GAME_UI_TEXT.md` is its format, and the engine loads it at start-up from `Content/UI/`). A shared button group is the reference `Resource("ButtonGroups/<name>[_unpress].ocbuttongroup")`, which names no file. `COMPONENT Props` on the widget nodes with Godot's names (`text`, `bbcode_enabled`, `label_settings` as `Object(LabelSettings, ...)`, `button_group`, `shortcut` as `Object(Shortcut, "events": [Object(InputEventKey, ...)])`, `theme_override_fonts/font` as `Resource("Fonts/...")` or `Object(FontVariation | SystemFont, ...)`, the dynamic item keys above, every enum as its integer). A widget the runtime lacks (`CodeEdit`, `MenuBar`, `FileDialog`, `GraphEdit`, `GraphNode`, `VideoStreamPlayer`, `ReferenceRect`) stays a `Control` carrier naming its class.
